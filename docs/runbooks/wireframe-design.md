# Wireframe Design Runbook

## Purpose
将产品定义和 PRD 收敛为可进入视觉设计或前端实现的页面结构说明。

## Inputs
- `docs/context/*`
- `docs/status/DECISIONS.md`
- `docs/tasks/active/CURRENT_TASK.md`
- 上一阶段产出（通常是 PRD / IA）

## Output Destination
- `docs/outputs/003-wireframes-output.md`

## Required Sections
1. 页面清单
2. 每个页面的目标
3. 每个页面的主要模块
4. 页面间跳转关系
5. 核心用户路径
6. 必做元素
7. 可后置元素
8. 设计风险与待确认点

## Design Rules
- 首页必须一眼体现：现在发生了什么、下一步做什么
- 拟人化是组织信息的手段，不是装饰
- 每个页面优先承载一个主要目标
- 尽量减少传统后台式多层菜单
- 页面结构说明应能直接被设计师或前端消费

## Completion Checklist
- 页面边界清晰
- 主路径完整
- 模块级结构足够具体
- 已写入输出文件
- 已更新状态文件
