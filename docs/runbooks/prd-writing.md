# PRD Writing Runbook

## Goal
Turn a validated product direction into a development-ready PRD for `business-os-v3`.

## Required Inputs
- `docs/context/*`
- `docs/status/DECISIONS.md`
- `docs/tasks/active/CURRENT_TASK.md`
- Previous output files from `docs/outputs/`

## Recommended Structure
1. Background and goal
2. Target user and problem
3. Product objective
4. Scope / non-goals
5. Key user flows
6. Functional requirements
7. States and edge cases
8. Metrics / validation plan
9. Risks / open questions

## Rules
- Use product language that a founder, designer, and engineer can all read.
- Tie every feature to business value or user clarity.
- Avoid abstract AI wording when a team-management metaphor is clearer.
- Define what needs real implementation vs. what can be mocked in the MVP.

## Deliverable Rule
Write the final artifact to the output file specified in the task card.
