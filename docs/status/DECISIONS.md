# Decision Log

## D-001 — 当前仓库定位为“可演示产品原型”
- **状态**：accepted
- **日期**：2026-03-27
- **决策**：将 `business-os-v3` 定位为已经具备基础产品演示能力的原型仓库，而不是从零开始的产品空白仓库。
- **依据**：
  - 已有 dashboard / skills / workflows 三个核心页面
  - 已有完整的 agent / workflow mock data
  - 已有视觉系统与交互壳子
- **影响**：
  - harness 的首要目标不是重新定义产品，而是建立长期自主执行框架
  - 后续任务将基于现有 UI demo 向 PRD、线框和 MVP 演化

## D-002 — Harness 第一版采用“任务完成后自动续跑下一任务（无阻塞时）”
- **状态**：accepted
- **日期**：2026-03-27
- **决策**：默认执行策略为：当前任务完成且命中自动续跑条件时，Cursor 应自动进入下一任务，不必等待用户再次发消息。
- **影响**：
  - 需要明确 `CURRENT_TASK.md`、`STATE.md` 与任务卡中的 `Next Task`
  - 需要严格限制 interruption conditions，避免 agent 过早停下

## D-003 — Harness 文件写入 repo，聊天不作为唯一事实来源
- **状态**：accepted
- **日期**：2026-03-27
- **决策**：产品定义、PRD、状态、风险、决策、任务卡等正式信息必须落盘到 repo 文件中，而不能只存在于聊天记录里。
- **影响**：
  - 新会话可以通过读取 repo 文件恢复状态
  - 项目可以在多台电脑 / 多次会话中连续推进
